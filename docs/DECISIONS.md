# Decisions made during autopilot

Append one short entry per decision: date, what was decided, why. Newest last.

- 2026-11-25: Autopilot started. Claude may merge its own PRs when build and tests pass. Matching is rules-first (see `claude/MATCHING_DESIGN.md` in the Sloffer Project for background); AI scoring is deferred.
- 2026-11-25: Jobs API `minScore` hides only scored jobs below it; unscored jobs (score null) are always listed and sort last under `sort=score`. Why: the spec asks for "nulls last" ordering (so nulls must be visible by default) and unscored rows have not been judged yet, so hiding them would silently drop jobs until a rescore runs. `sort` is case-sensitive (`score`/`posted`), matching the other lowercase query values. (PR #13)
- 2026-11-25: Real-data check (roadmap item 4), first run: 135 jobs (Jobicy 103 fetched, Arbeitnow 34 kept of 1500), 119 scored 0. Two hard-rule bugs found: (1) the `.NET` term matched domain names in descriptions (`Risk.net`, `ctfassets.net`, `godaddy.net`), so a fraud-analytics manager, a regulatory lead and an account executive passed as .NET jobs; `TermMatcher` now needs a word boundary on the left for every term (`ASP.NET` is its own term). (2) 15 Arbeitnow jobs were rejected as "location not in EMEA" because Arbeitnow writes `Deutschland`/`Nederland` or only a city (`London`, `Amsterdam`, `Stuttgart`), including a real ".NET" role in Woerden; added local-language country names and ~90 major EMEA cities to `EmeaLocations`. "Porto" left out on purpose (Porto Alegre). Small towns given without a country (e.g. "Mühldorf") still fail; acceptable for now. `JobScorer.Version` 1 -> 2. (PR #14)
- 2026-11-25: Real-data check, second fix: domain soft-rule terms were mostly matching benefits and logistics, not the employer's business: `insurance` (83 hits, nearly all "health/life insurance"), `travel` (53, "ability to travel up to 25%"), `bank` ("bank holidays"). Replaced the bare words with business phrases (`insurtech`, `insurance claims`, `digital bank`, `bank accounts`, `financial crime`, `financial services`, `online travel`, ...). Each phrase is its own entry so the reason names what matched. `JobScorer.Version` 2 -> 3. (PR #15)
- 2026-11-25: Frontend MVP (sloffer-frontend#1). Kept the repo's existing oxlint instead of adding ESLint (same job, already wired, 0-warning rule). `openapi-typescript` needs TypeScript 5 and the repo is on 7, so `npm run api:generate` runs a pinned `openapi-typescript@7.13.0` via `npx` instead of adding it as a dev dependency; the generated `schema.d.ts` is committed. New deps: `react-router` (routes + URL search params), `dompurify` (spec). Design details: filters in the URL with short names (`q`, `location`, `source`, `minScore`, `sort`, `posted`, `duplicates`, `page`) and defaults left out; the frontend always sends every API parameter explicitly (so "Last 7 days" means 168 h even if `JobFetch:MaxAgeDays` changes); text filters apply on submit, selects and the checkbox apply at once; any filter change resets to page 1; minimum-score choices Any / 1+ / 45+ / 60+; score badge green >= 60, amber 45-59, red < 45; the old backend-health page was replaced by the jobs page. The OpenAPI schema types `score` as `number | string` (ASP.NET number handling), so the UI normalises it with `scoreValue`.
- 2026-11-25: Scoring v2 PR 1 (role gate). The title alone decides whether the job is a software engineering IC role: a title term from `RoleRejectTitleTerms` gives 0 with "role: <term>", and a title with no `EngineeringTitleTerms` word gives "role: title is not an engineering role" ("consultant" only gives its own reason when no engineering word is present). A reject term wins even with an engineering word ("Senior QA Engineer" -> "role: qa"). Additions to the spec's lists, from real Arbeitnow/Jobicy titles: frontend/front-end, android, ios (not backend); internship, werkstudent, praktikum, ausbildung, duales studium, stagiaire (too junior); German/French engineering words (entwickler, softwareentwickler, ingenieur, développeur). "stage" left out (also English "early-stage"). The old seniority hard rule now only covers staff/principal (PR 3 turns them into penalties); junior/intern/director/head of/VP/chief moved into the role gate. Golden examples live in `tests/Sloffer.Tests/Matching/GoldenJobs/golden-jobs.json`; cases for rules from later PRs carry a `pending` note and run in a skipped theory until then. `JobScorer.Version` 3 -> 4.
- 2026-11-25: Scoring v2 PR 2 (.NET centrality). Replaces "title mentions .NET +15". A .NET-family match is *weak* when its clause (line from the HTML structure, cut at sentence ends but not after "e.g.") names another language together with an alternatives word ("or", "e.g.", "such as", "any of", ...) or a "/", when the clause carries a nice-to-have marker ("a plus", "a bonus", "preferred", "von Vorteil", ...), or when it comes after a short heading line with such a marker (<= 50 chars, no language name, not a sentence like "Docker is a plus"). Core = a strong match in the title, or >= 2 strong matches in the description: +25. Otherwise only mentioned: no points and the final score is capped at 50, so it can never reach the default list (55+). "Go" is not in `OtherLanguageTerms` (English verb), only "Golang"; bare "C" is not either (it would match inside "C#"). "C# and Python" stays strong (both required); "C#/.NET" stays strong (no other language). All weights and term lists are `JobScoring` options. `JobScorer.Version` 4 -> 5. (PR #17)
- 2026-11-25: Scoring v2 PR 3 (seniority, bands, API default). Seniority: senior/sr, mid/middle/medior/regular and a plain title all +5 ("good fit"; mid used to be +10, the spec treats them the same); lead -5 (was -10); staff/principal -15 and no longer a hard reject (reason "staff title (usually 8+ years)"). Years asked: <= 6 +5, 7-9 -8, >= 10 -20 (new `TooManyYearsMin`/`TooManyYearsPoints`). Bands: 75-100 Excellent, 55-74 Good, 35-54 Maybe, 1-34 Weak, 0 rejected; no new API field, the UI derives the band from the score. `GET /api/jobs` `minScore` default 1 -> 55 (`JobListQuery.DefaultMinScore`). Calibration on the golden set: ideal senior .NET backend job 84, staff C# 59, real LastPass/Iits/Woerden .NET jobs 67-73. `JobScorer.Version` 5 -> 6. (PR #18)
- 2026-11-25: Sandro's answers for strict matching (`docs/next/strict-matching-v3.md`): only Excellent (75+) jobs in the list, at most 100 a day; Excellent needs remote in EMEA or relocation/visa; .NET must be the stack (other-language jobs out, polyglot jobs only when .NET is core); English listings only, he does not speak German; plus a Viewed mark. Sources picked by Claude: Remotive and Remote OK (public, no key). Probing both: Remotive's `.net` search is fuzzy (fetch the software-dev category and let the scorer filter); Remote OK `tag=c#` returns nothing, the full feed is ~100 mostly US jobs, and its terms forbid using its logo, so source "icons" are monogram badges for every source. Free remote boards add only a few .NET EMEA jobs a day; Adzuna (free key) is the realistic way to ~100, roadmap 7b blocked on a key.
- 2026-11-25: Scoring v3 (strict). Listing language by stop-word counts (distinctive words only, English vs German/Dutch/French, texts under 25 words skipped). Required spoken language by phrase lists ("fluent German", "Deutschkenntnisse", "Dutch speaker", ...), ignored when the clause carries a nice-to-have marker. Title-language rule uses its own list where "Go" is allowed (in titles it means the language). Polyglot: -8 per other core language (strong mention outside alternatives lists / nice-to-have), max -16, only when .NET is core. Location fit: on-site or hybrid without relocation/visa capped at 70; remote-only sources count as remote; "hybrid" in title or location wins over description remote phrases. Unit tests lift the cap (`OnSiteMaxScore = 100` means off) to keep isolating single rules; golden examples use real defaults. 12 new golden cases (2 from real listings: Infomedics Dutch listing, SwissPeak on-site Luzern). `JobScorer.Version` 6 -> 7.
